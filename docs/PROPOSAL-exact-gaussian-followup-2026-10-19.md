# Proposed exact-Gaussian follow-up after I6 FAIL (2026-10-19)

**Status: review proposal, no method selection or run authorization.** I6's prespecified candidate d failed s6/N=1000 on coverage equivalence and width (`docs/reports/I6-GATE-2026-10-19.md`). Its exact reference e is a useful candidate for a *new* decision; comparing e with itself cannot reverse the I6 verdict. The pmed submission hold and the stop before I7 remain in force.

## Scope and source audit

The existing `inst/sim/hopper/i6/runner.R::exact_pmed()` fits `M ~ X` and `Y ~ X + M` on each bootstrap sample, then evaluates `Phi(ab / sqrt(2(b^2 sigma_M^2 + sigma_Y^2)))`. It uses residual scales from `SSE/df.residual`, as in those bootstrap refits. For additive Gaussian models with treatment contrast `delta = x_value - x_ref`, the numerator is `delta*a*b`; direct effect and shared covariates cancel when both potential outcomes hold treatment and covariates fixed. The formula requires the independent nested-outcome coupling used by the simulation. It does not establish joint A2 or support binary, ordinal, count, interaction, heteroscedastic, or arbitrary SEM models. Reject nonfinite fits and specify the deterministic/tie boundary when the denominator is zero.

The manuscript simulation's nonparametric percentile interval, the package's default **parametric** bootstrap, and its opt-in **model-based response** bootstrap use different resampling laws. Currently `R/compute-core.R`, `R/compute-bootstrap.R`, and `R/compute-model-bootstrap.R` call the simulated single-mediator core; the parallel Gaussian path has a separate closed-form kernel. I6 e validates none of those package methods automatically. Do not globally replace `.pmed_core_simple()` or change a public default from this result. A package API change needs a separate feature branch and method-specific tests and documentation.

## Proposed validation sequence

1. **Freeze a candidate and implementation before further outcomes.** Candidate E is exact Gaussian evaluation *inside each nonparametric bootstrap resample* for the same additive single-mediator model as the pmed Gaussian scenarios. Preserve 2,000 bootstrap draws, percentile definition, and the all-attempt denominator. Use a new full-run seed family, proposed `20261021`, disjoint from I2/I4 (`20261016`), I6 (`20261017`), and the resource pilot (`20261020`). Exclude the pilot output from the prospective grid. Fix the runner hash, task grid, acceptance script, and failure mapping in a manifest before submitting a full array. The one-task pilot is recorded in `docs/reports/EXACT-GAUSSIAN-6K-PILOT-2026-10-19.md`; it does not authorize the full array.
2. **Prove the numerical kernel independently, locally.** Derive the normal-difference formula on paper, including `delta`, direct-effect cancellation, shared-covariate cancellation, and the zero-denominator tie case. Compare an implementation using the extracted coefficients and residual scales with an independently coded one-dimensional integral `E_D[Phi(b*D/(sqrt(2)*sigma_Y))]`, where `D ~ N(a*delta, 2*sigma_M^2)`, on fixed parameter fixtures; require absolute error <= `1e-8`. Include positive/negative a and b, reversed/non-unit treatment contrasts, zero a or b, unequal residual scales, factor covariates, and a direct-effect perturbation. Check supported-family/structure guards. Test a forced nonfinite refit and require explicit failed-draw accounting rather than `na.rm=TRUE` silently discarding it. Keep MBCO's likelihood MLE scale distinct from the bootstrap's residual-df scale.
3. **Replay retained evidence as a regression check.** Select two outer replications per I2 and I6 Gaussian cell, including s6/N=1000 and edge cases, *before* running the new implementation. Reconstruct their datasets and bootstrap-index streams from the recorded seeds and worker topology; compare all selected exact point estimates and interval endpoints by `(scenario,N,rep)`, requiring no missing selected key and max absolute difference <= `1e-12` on identical resamples. Independently scan the *stored* I2/I6 output grids for full key completeness, finite intervals, and hashes; avoid recomputing all 130 million retained bootstrap fits solely for this regression check. The replay checks source integration and provenance, not independent coverage. Confirm fixed-data scores against high-precision direct simulation as a separate sanity check.
4. **Prospective confirmation for any new coverage wording.** Revised proposed grid: s1, s6, s7, s8 at N = 50, 100, 250, 500, 1000, with 6,000 outer replications and 2,000 nonparametric resamples per cell, subject to a frozen compute ceiling and separate author approval for the full run. The author selected 6,000 while accepting that a boundary result may be inconclusive; do not increase replications after seeing the result to rescue a claim.

   **Integrity and reporting.** Validate every chunk hash, expected replication key, bootstrap count, finite interval, and failure count before analysis. Count incomplete outer intervals as noncoverage and report them separately; do not drop them from the denominator. Use closed-form truths (s6/s7 exactly 0.5), with no cross-run pairing to I2/I6. Report per-cell coverage, Monte Carlo SE, two-sided 95% exact-binomial intervals, mean width, and point-estimate behavior.

   **Minimum-coverage gate.** For the six s6/s7-by-N cells at N = 250, 500, 1000, the author selected **94% as the minimum acceptable true coverage**. Require the one-sided 95% exact-binomial *lower* confidence bound to exceed 0.94 in **every** cell. This intersection-union all-cells rule is not an average; no adjustment across the six cells is needed for the joint minimum-coverage claim. At 6,000 replications, a cell needs at least 5,671 covered intervals (94.52% observed) to clear the lower-bound rule. If its true coverage is 94.25%, its pass probability is about 20%. This conditional calculation is not a prediction or a reason to relax the rule.

   **Interpretation.** If a cell's one-sided 95% *upper* bound is below 0.94, flag evidence of undercoverage in that cell; this is a per-cell assessment, not a familywise claim about which cell fails. If neither bound clears 0.94, classify that cell as **inconclusive and needing further scrutiny**, not as adequate or inadequate. Either outcome withholds the joint minimum-coverage claim. Prior I2/I6 results and the pilot are exploratory/regression evidence, not additional opportunities to pass this gate; only the fresh-seed run makes the formal coverage decision. There is no upper coverage cutoff: report and investigate interval width separately, without a width pass/fail threshold for the minimum-coverage claim. Passing this lower-bound gate alone cannot establish the stronger phrase “near nominal”: unusually high observed coverage or wide intervals must be disclosed and considered in a separate author review of any such wording. Small-N s6 overcoverage and s1/s8 results remain per-cell disclosures, never folded into the six-cell claim.
5. **Package work stays separate.** If the author chooses package integration, first define whether exact Gaussian evaluation applies to `plugin`, parametric, nonparametric, or model-based bootstrap, and preserve each method's resampling law, result slots, convergence/failure semantics, and seeded behavior. Make it opt-in or versioned until the behavior and `n_sim` meaning are reviewed. Add model-specific tests, then run probmed's required documentation, tests, `rcmdcheck`, coverage, and pkgdown verification. Search README, help, vignettes, man pages, and site content for stale Monte Carlo guidance. Do not infer binary calibration from Gaussian E.

## Decision mapping

| Result | Disposition |
|---|---|
| Formula/oracle, row completeness, or source replay fails | Stop. Repair the implementation or provenance; no numerical promotion. |
| Checks pass, and all six prospective null cells clear the 94% lower-bound rule | Exact Gaussian becomes a *candidate* source for a six-cell minimum-coverage statement and separate pmed author review. The lower-bound rule alone does not justify “near nominal”; inspect coverage estimates, widths, all other cells, and failures before drafting. I7 and submission remain separately held. |
| Checks pass, but any null cell is inconclusive at 94% | Withhold the near-nominal claim; report per-cell estimates and uncertainty, audit the ambiguous cell, and recommend further investigation under a separately prespecified design. Do not silently add replications, change the gate, or start I7 automatically. |
| Checks pass, but any null cell has an upper one-sided 95% bound below 94% | Treat that cell as evidence of undercoverage; report estimates and limitations, withhold the near-nominal claim, and investigate. Do not start I7 automatically. |
| Run incomplete or budget exhausted | Report incomplete; no promotion or post-result gate change. |

**Review recommendation:** The author selected a 94% minimum-coverage gate in all six null cells, separate width reporting/investigation, and 6,000 outer replications per cell with inconclusive results allowed. This settles the proposed *minimum-coverage judgment rule*, not the stronger “near nominal” wording, the exact-Gaussian method, the full-run authorization, package API scope, or pmed wording. No pmed file, package behavior, or Hopper job was changed by this proposal.
